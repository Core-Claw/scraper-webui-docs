**方法:** `POST`

**端点:** `/api/v2/worker-runs/{runId}/rerun`

**认证:** 支持 `Authorization: Bearer <YOUR_API_KEY>`、`api-key: <YOUR_API_KEY>` 和 `?token=<YOUR_API_KEY>`。推荐优先使用 Bearer token。

## 在线试用

<ApiPlayground method="POST" path="/api/v2/worker-runs/{runId}/rerun" />

## 什么时候使用这个接口

用于基于已有运行创建新的运行，响应会返回新的 `run_slug`。

## 标识符说明

- `runId` 是运行记录 slug。启动或重跑后的 `data.run_slug` 就是后续接口使用的 `runId`。

## 路径参数

| 参数 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `runId` | 是 | `string` | 运行记录 slug，即启动或重跑响应中的 `data.run_slug`。 |

## 请求体

使用 `Content-Type: application/json` 发送请求体。表格中的必填/选填描述字段本身是否必须提供；整个请求体是否必填以在线试用区的 Request Body 标记为准。

| 字段 | 必填 | 类型 | 说明 |
| --- | --- | --- | --- |
| `callback_url` | 否 | `string` | 回调地址。传入后，CoreClaw 会在运行状态变化或结束时向该地址发送 `POST` 请求。 |
| `is_async` | 否 | `boolean` | `true` 表示异步提交，不等待执行结果；`false` 表示等待执行结果，直到运行完成。默认 `true`。**同步模式最多等待 5 分钟；超过 5 分钟仍未完成时，请求会先返回，需要改用运行查询接口轮询状态。** |
| `limit` | 否 | `integer` | 同步运行或重跑时返回的结果窗口大小；仅影响同步响应中附带的结果数量，不影响完整结果集。 约束：默认 `20`；范围 1-100。 |
| `offset` | 否 | `integer` | 同步响应结果窗口的页码，从 1 开始。`offset=1` 为第 1 页；`offset=0` 兼容作为第 1 页。仅影响同步响应附带的结果数量，不影响完整结果集。 约束：默认 `0`；最小 0。 |

### JSON 示例

```json
{
  "callback_url": "https://client.example.com/openapi/callback",
  "is_async": true,
  "limit": 20,
  "offset": 0
}
```

## 运行模式

- `is_async: true` 表示异步提交运行，不等待执行结果。响应会返回 `data.run_slug`，随后用运行详情、日志和结果接口轮询。
- `is_async: false` 表示等待执行结果，等价于等待运行执行完成的 run-and-wait；可配合 `offset` / `limit` 直接获取同步运行返回的数据窗口。

> **⚠️ 同步等待上限：5 分钟。** 当 `is_async: false` 时，平台**最多等待 5 分钟**。若运行在 5 分钟内未完成，请求仍会返回，运行会在后台继续执行——此时必须改用运行**查询接口**按 `runId` 轮询状态、日志和结果。预计运行可能超过 5 分钟时，建议使用 `is_async: true`。

## 请求示例

```bash
curl -X POST "https://openapi.coreclaw.com/api/v2/worker-runs/YOUR_RUN_ID/rerun" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{"callback_url":"https://client.example.com/openapi/callback","is_async":true,"limit":20,"offset":0}'
```

## 响应示例（异步）

当 `is_async: true`（默认）时，响应立即返回新的 `run_slug`：

```json
{
  "code": 0,
  "data": {
    "run_slug": "01KKDXV2G26BT7NH4ZQR2R4NPZ"
  },
  "message": "success",
  "request_id": "req-123"
}
```

## 响应示例（同步）

当 `is_async: false` 时，响应会等待重跑完成，并返回运行状态、时间信息和一个分页结果窗口。`results` 对象的结构与 `GET /api/v2/worker-runs/{runId}/result` 一致。重跑同步响应包含 `is_finished`，不含 `error_message`/`result_message`：

```json
{
  "code": 0,
  "data": {
    "run_slug": "01KZAZTK3BEMEDXA54396WMGC2",
    "run_status": "succeeded",
    "execution_start_timestamp": 1786001000,
    "execution_end_timestamp": 1786001008,
    "running_duration": 8,
    "is_finished": true,
    "results": {
      "count": 1,
      "headers": [
        { "key": "title", "label": "Title" }
      ],
      "list": [
        { "title": "Example result" }
      ],
      "page_index": 1,
      "page_size": 2
    }
  },
  "message": "success",
  "request_id": "req-123"
}
```

### 同步响应字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `data.run_slug` | `string` | 新运行标识。用于读取详情、日志、结果和导出。 |
| `data.run_status` | `string` | 运行状态，例如 `succeeded` 或 `failed`。详见[运行生命周期与状态](/zh-cn/api/run-lifecycle/)。 |
| `data.execution_start_timestamp` | `integer` | 执行开始时间，Unix 秒。 |
| `data.execution_end_timestamp` | `integer` | 执行结束时间，Unix 秒。 |
| `data.running_duration` | `integer` | 运行时长，秒。 |
| `data.is_finished` | `boolean` | 同步等待返回时运行是否已进入完成状态。 |
| `data.results` | `object` | 分页结果窗口。结构与结果接口一致：`count`、`headers`、`list`、`page_index`、`page_size`。详见[查询运行结果](/zh-cn/api/worker-runs/result/)。 |

> `run_status` 是权威状态。如果 `is_finished` 为 `false` 或同步等待超时，请通过运行详情接口轮询最终状态。

## 注意事项

- API v2 同时支持 Bearer token、旧版 `api-key` 请求头和 query token；新集成建议优先使用 Bearer token。
- 运行状态、轮询、失败诊断和取消处理请参阅[运行生命周期与状态](/zh-cn/api/run-lifecycle/)。
- 传入 `callback_url` 后，CoreClaw 会在运行状态变化或结束时发送回调通知。详见[回调通知](/zh-cn/api/callbacks/)。
