**Method:** `GET`

**Endpoint:** `/api/v2/run-queue/items`

**Authentication:** Supports `Authorization: Bearer <YOUR_API_KEY>`, `api-key: <YOUR_API_KEY>`, and `?token=<YOUR_API_KEY>`. Prefer Bearer token.

## Try it

<ApiPlayground method="GET" path="/api/v2/run-queue/items" />

## When to use this endpoint

Use this endpoint to inspect the Run Queue — items waiting to be activated or items that have become inactive. It is the read-side companion to the activate and release operations, useful for monitoring queue depth and deciding which items to activate or release next.

## Query Parameters

| Parameter | Required | Type | Description |
| --- | --- | --- | --- |
| `offset` | No | `integer` | Pagination offset, starting from 0. Constraints: default `0`; minimum 0. |
| `limit` | No | `integer` | Page size. `limit` is capped at `100` on list endpoints. Constraints: default `20`; range 1-100. |
| `status` | No | `string` | Queue status filter. Allowed values: `waiting`, `inactive`. |

## Request Example

```bash
curl -X GET "https://openapi.coreclaw.com/api/v2/run-queue/items?offset=0&limit=20&status=waiting" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## Response Example

```json
{
  "code": 0,
  "data": {
    "count": 1,
    "list": [
      {
        "queue_ref": "123456",
        "queue_status": "waiting",
        "worker_id": "demo-worker"
      }
    ]
  },
  "message": "success",
  "request_id": "req-123"
}
```

> The exact fields inside `data.list[]` depend on the queue item shape returned by the platform. Treat `queue_ref` as the identifier you pass to the activate and release endpoints.

## Notes

- API v2 supports Bearer token, the legacy `api-key` header, and query token. Prefer Bearer token for new integrations.
- `queue_ref` values returned here are the IDs used by [Activate Run Queue Items](/api/run-queue/activate-items/), [Release Run Queue Items](/api/run-queue/release-items/), and [Release One Run Queue Item](/api/run-queue/release-item/).
- See [Run Lifecycle & Status](/api/run-lifecycle/) for background on run states; queue items represent runs that have not yet been activated.
