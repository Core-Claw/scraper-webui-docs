**Method:** `POST`

**Endpoint:** `/api/v2/run-queue/items/activate`

**Authentication:** Supports `Authorization: Bearer <YOUR_API_KEY>`, `api-key: <YOUR_API_KEY>`, and `?token=<YOUR_API_KEY>`. Prefer Bearer token.

## Try it

<ApiPlayground method="POST" path="/api/v2/run-queue/items/activate" />

## When to use this endpoint

Use this endpoint to activate one or more queued items in a single batch call. Activating an item moves it from the waiting state toward execution. Collect `queue_ref` values from [List Run Queue Items](/api/run-queue/list-items/) first.

## Request Body

Send the request body with `Content-Type: application/json`.

| Field | Required | Type | Description |
| --- | --- | --- | --- |
| `queue_refs` | Yes | `array<string>` | Queue item IDs to activate. Pass the `queue_ref` values from [List Run Queue Items](/api/run-queue/list-items/). May be `null`/empty, but to activate items you must populate it. |

### JSON Example

```json
{
  "queue_refs": ["123456", "123457"]
}
```

## Request Example

```bash
curl -X POST "https://openapi.coreclaw.com/api/v2/run-queue/items/activate" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{"queue_refs":["123456","123457"]}'
```

## Response Example

```json
{
  "code": 0,
  "data": {},
  "message": "success",
  "request_id": "req-123"
}
```

## Notes

- API v2 supports Bearer token, the legacy `api-key` header, and query token. Prefer Bearer token for new integrations.
- This is a batch operation; every `queue_ref` in the array is activated. To release items instead, use [Release Run Queue Items](/api/run-queue/release-items/).
- See [Run Lifecycle & Status](/api/run-lifecycle/) for status handling and polling after activation.
