**Method:** `POST`

**Endpoint:** `/api/v2/run-queue/items/release`

**Authentication:** Supports `Authorization: Bearer <YOUR_API_KEY>`, `api-key: <YOUR_API_KEY>`, and `?token=<YOUR_API_KEY>`. Prefer Bearer token.

## When to use this endpoint

Use this endpoint to remove one or more runs from the Run Queue so they never execute — for example, when you no longer need a waiting run. This is the batch version: pass multiple `queue_ref` values in one call. To release just one item, use [Release One Run Queue Item](/api/run-queue/release-item/) instead.

First call [List Run Queue Items](/api/run-queue/list-items/) to get the `queue_ref` of the items you want to release.

## Request Body

Send the request body with `Content-Type: application/json`.

| Field | Required | Type | Description |
| --- | --- | --- | --- |
| `queue_refs` | Yes | `array<string>` | The queue item IDs to release. Copy these from the `queue_ref` values returned by [List Run Queue Items](/api/run-queue/list-items/). |
| `reason` | No | `string` | Optional reason for releasing, recorded for your later reference. |

### JSON Example

```json
{
  "queue_refs": ["123456", "123457"],
  "reason": "no longer needed"
}
```

## Request Example

```bash
curl -X POST "https://openapi.coreclaw.com/api/v2/run-queue/items/release" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  --data '{"queue_refs":["123456","123457"],"reason":"no longer needed"}'
```

## Response Example

```json
{
  "code": 0,
  "data": {},
  "message": "success",
  "request_id": "req-123"
}
```

## Notes

- API v2 supports Bearer token, the legacy `api-key` header, and query token. Prefer Bearer token for new integrations.
- Releasing is permanent: the item is removed from the queue and will not run. If you want the run to execute instead, use [Activate Run Queue Items](/api/run-queue/activate-items/).
- See [Run Lifecycle & Status](/api/run-lifecycle/) for status handling and cancellation behavior.
